# 검증 설계와 제품 선정

> 이 문서는 보조 기능인 반복 평가의 설계입니다. 제품의 기본 흐름은 모델을 선택하고 자유롭게 대화·음성 생성을 시험하는 웹 페이지입니다. 현재 실행 방법과 개발 우선순위는 [README](../README.md)를 기준으로 합니다. 아래 평가 확장은 플레이그라운드 기능보다 우선하지 않습니다.

## 목표

‘가장 좋은 모델’ 하나를 정하기보다 **제품 제약을 만족하는 조합과 그 근거**를 남깁니다. 빠른 응답, 한국어 말투, 인식 정확도, 자원 사용량, 배포 가능성은 따로 평가합니다.

## 1. 비교 실험을 분리

| 실험 | 고정할 조건 | 바꿀 항목 | 산출물 |
|---|---|---|---|
| TTS 단독 | 같은 한국어 문장, 재생 환경 | 엔진·목소리·steps·감정 지시 | WAV, 파일 완성 시간, RTF, 사람 평점 |
| LLM 단독 | 질문·대화 이력·답변 길이 지침 | 모델·양자화·추론·컨텍스트 | 답변, 첫 텍스트 지연, 완료 시간 |
| STT 단독 | 같은 녹음과 사람이 작성한 전사 | 모델 크기·장치·VAD 설정 | 전사, CER/WER, 처리 RTF |
| 파일 기반 조합 | 같은 질문/녹음, 장치 | STT·LLM·TTS 조합 | 단계별 시간, 최종 답변과 음성 |
| 실시간 조합 (후속) | 마이크·스피커·소음·종료 감지 | 청크 길이·버퍼·끼어들기 | 첫 실제 재생 지연, 끊김, 취소 반응 |

TTS 단독에서는 동일 문장을 사용합니다. 조합 실험에서 서로 다른 LLM 답변은 길이와 내용이 달라지므로, TTS 자체의 우열을 추론하지 않습니다. 동일한 브랜드의 서로 다른 모델도 같은 추론 옵션을 지원한다고 가정하지 않습니다.

## 2. 한국어 데이터 확장

현재 데이터는 직접 작성한 12개 TTS 문장과 6개 대화 시나리오입니다. 모델 순위 확정에는 부족합니다.

- 일상 대화, 공감, 질문, 설명, 반말·존댓말, 짧은 대답.
- 받침·연음, 숫자·날짜·금액·단위, 영어 혼용, 실제 프로젝트의 고유명사.
- 긴 대화의 맥락, 사용자의 정정, 알려주지 않은 사실, 모호한 지시.
- STT는 화자·성별·발화 속도·마이크·조용함/소음 조건별 실제 녹음.
- 원문과 전사는 평가 전에 고정합니다. 특정 엔진에만 유리한 표기 보정은 별도 실험으로 기록합니다.

검증 데이터와 최종 확인용 데이터를 분리합니다. 설정을 반복 조정한 데이터의 점수만으로 채택하지 않습니다. 운영에서 사용할 말투·문장 길이가 데이터 분포에 반영되어야 합니다.

## 3. 반복과 지연 해석

첫 탐색은 같은 조건으로 3회 반복합니다. 최종 후보는 문장을 충분히 늘리고 다른 실행 시점에도 재측정합니다. 작은 표본의 p95는 참고값입니다. 현재 도구는 신뢰구간이나 유의성 검정을 제공하지 않습니다.

워커 초기화 시간에는 프로세스 시작과 라이브러리 import가 포함됩니다. 본 측정은 워밍업 이후입니다. HTTP 서버는 도구 밖에서 이미 적재됐을 수 있으므로 초기화 시간이 모델 로딩 시간을 뜻하지 않습니다. Ollama가 제공하는 서버 측 load/eval 시간은 별도 지표입니다.

각 실험은 순차 실행합니다. 입력 순서는 seed로 재현되지만, 실험 순서는 설정 순서입니다. 열·캐시·시간 경과 영향을 확인하려면 후보 순서를 뒤집은 별도 실행도 보관합니다. 서버 캐시가 남는 상황과 완전히 새로 시작한 상황은 구분합니다.

## 4. 사람이 평가할 기준

블라인드 화면에서 동일 문장 필터를 선택해 후보를 차례로 듣습니다. 모델명은 숨기지만 목소리 자체로 모델을 알아볼 수 있으므로 완전한 맹검을 보장하지 않습니다. 최초 버전은 샘플별 평점이며 강제 A/B 선호 투표는 아닙니다.

| 항목 | 1점 예시 | 3점 예시 | 5점 예시 |
|---|---|---|---|
| 자연스러움 | 기계적으로 들려 대화가 어려움 | 어색한 부분이 있으나 사용 가능 | 일상 대화로 편하게 들림 |
| 발음 | 누락·오독 때문에 의미가 바뀜 | 일부 오독 있으나 이해 가능 | 고유명사·숫자까지 정확 |
| 억양·쉼·감정 | 질문/감정과 어긋남 | 대체로 맞지만 단조로움 | 상황과 문장 구조에 잘 맞음 |
| 내용 적절성 | 맥락을 놓치거나 잘못 인식 | 주로 맞지만 수정 필요 | 의도와 맥락을 정확히 반영 |

적용할 수 없는 항목은 ‘평가하지 않음’으로 둡니다. 평점은 서로 다른 평가자 여러 명에게 받고, 반복 음성 수와 고유 문장 수를 구분해서 해석합니다. 평점 평균은 이 실험의 주관 평가이며 공인 MOS라고 부르지 않습니다.

## 5. 제품 채택 기록

최종 선택 전 [선정 기록 템플릿](SELECTION_TEMPLATE.md)에 실행 ID·환경·조건·한계·결정을 남깁니다. 지연 하나만으로 자동 순위를 만들지 않습니다.

1. 필수 기능과 발음·실패율 조건을 통과한 후보를 추립니다.
2. 자연스러움과 응답 지연이 서로 개선되는지, 한쪽이 희생되는지 확인합니다.
3. 선택한 조합으로 별도의 최종 확인 데이터를 실행합니다.
4. 모델·음색·추론 옵션·버전을 고정해 실제 프로젝트에 넘깁니다.
5. 실시간 경로에서 첫 실제 음성·끼어들기·장시간 자원 사용을 확인한 후 운영에 채택합니다.

## 단계별 개발 범위

- **현재:** 어댑터, JSON 실험 목록, 반복 측정, 원시 결과/CSV/보고서, 파일 기반 조합, 블라인드 평점.
- **다음:** 여러 실행 통합 비교, 모델 파일 해시 자동 수집, 실험별 자원 샘플링, 장애 원인 분류, 청취 A/B 선호 투표.
- **실시간 검증:** 마이크 입력, VAD/발화 종료 판단, 부분 STT, TTS 청크, 재생 버퍼, 끼어들기 취소, 오디오 루프백 측정.
- **제품 이전:** 고정 버전 설치, 기준 미달 감지, 장시간 테스트, 실패 시 대체 엔진, 통합 설정 내보내기.

초기 참고 목표인 ‘사용자 발화 종료 후 1~1.5초’는 실측값도 현재 파일 기반 벤치마크의 보장도 아닙니다. 실제 요구사항에 맞춰 확정해야 합니다.
